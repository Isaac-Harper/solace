# Deployment (Modrinth)

Solace publishes to Modrinth with the [Mod Publish Plugin](https://github.com/modmuss50/mod-publish-plugin),
the same setup as the sibling Mirror / Fallow / Shulker Pocket projects. A `v*` git tag triggers
the publish in CI; a local publish works too.

## One-time setup

1. **Generate a Modrinth PAT** at <https://modrinth.com/settings/pats> with the **Create projects**,
   **Write projects**, and **Create versions** scopes, and paste it into `.env` (gitignored).
2. **Create the project**: `scripts/modrinth_bootstrap.sh`. It creates the listing (slug `solace-mod`,
   summary from the script, body from `README.md`), uploads `icon.png`, and writes the returned
   project id into `gradle.properties` as `modrinth_id`. (Or do the same by hand at
   <https://modrinth.com/dashboard/projects>: type Mod, loader Fabric, client optional / server
   required, categories Game Mechanics + Utility, then paste the id into `gradle.properties`.)
3. **For CI publishing**: `gh secret set MODRINTH_TOKEN` (repo secret used by both workflows).

## Publish

- **Via CI (preferred):** push a version tag, e.g. `git tag v1.0.0 && git push origin v1.0.0`. The
  `build` workflow builds + tests, then the `publish` job uploads the jar to Modrinth and syncs the
  README as the project page. `workflow_dispatch` does the same on demand.
- **Locally:**
  ```sh
  set -a; source .env; set +a      # load MODRINTH_TOKEN
  ./gradlew publishMods
  ```

Without a `MODRINTH_TOKEN` the publish **dry-runs**: it builds the jar and validates the config but
uploads nothing (`./gradlew publishMods` is a safe way to check the wiring).

The listing starts as a draft; it goes live once it has a version and you press Publish on the
project page.

## Files involved

- `build.gradle` - the `publishMods { modrinth { ... } }` block (project id, game version,
  `requires("fabric-api")`, `optional("modmenu")`, `optional("cloth-config")`); the version string
  carries the MC version (`1.0.0+26.1.2`) so each MC port is a distinct Modrinth version.
- `gradle.properties` - `modrinth_id`, `mod_version`, `minecraft_version`.
- `CHANGELOG.md` - the `## <mod_version>` section becomes the Modrinth changelog for that release.
- `.github/workflows/build.yml` - CI build + tag/dispatch publish + body sync.
- `.github/workflows/sync-body.yml` - re-sync the project page from the README without a new version.
- `icon.png` / `src/main/resources/assets/solace/icon.png` - generated by `icon_art.py`.
- `scripts/modrinth_bootstrap.sh` - one-time project creation.
